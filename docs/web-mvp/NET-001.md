# NET-001 — серверный авторитетный контур, комнаты, инвайт-ссылки

Целевая схема (из `docs/architecture.md` и аудита P3):

```
клиент (Godot Web)  ⇄  WebSocket  ⇄  сервер (Godot headless)  ⇄  состояние матча
```

Сервер — единственный источник истины: применяет правила, проверяет право игрока,
фазу/ход, ресурсы и геометрию. Клиент шлёт намерения, рисует присланное состояние.
Правила — тот же GDScript `scripts/rules/*` (дублирования на втором языке нет).

## Транспорт (проверено)

`tests/websocket.gd` — headless Godot поднимает `TCPServer` + `WebSocketPeer`,
клиент подключается и гоняет JSON в обе стороны (ping/pong). 4 проверки PASS.
Это базовый транспорт сервера.

## Протокол (JSON)

Сообщение: `{type, payload, seq}`. Типы:

| type | кто → кому | смысл |
|---|---|---|
| `hello` | клиент → сервер | гость: ник, версия клиента |
| `welcome` | сервер → клиент | выдана временная identity (`guest_id`), id комнаты |
| `create_room` | клиент → сервер | создать комнату → ответ `room_created{invite_token}` |
| `join_room` | клиент → сервер | войти по `invite_token` → `seat_assigned{player}` |
| `choose_faction` | клиент → сервер | выбор фракции на своё место |
| `intent` | клиент → сервер | намерение хода (move/attack/action/end_turn) |
| `state` | сервер → всем | полное/дельта состояние матча |
| `event` | сервер → всем | события для анимаций (удар, ранение, гибель) |
| `rejected` | сервер → клиент | отказ с причиной (тот же текст — в UI игроку) |
| `match_started` / `match_finished` | сервер → всем | старт/победа (результат, реванш) |

## Комната

- Создаётся по `create_room` → непредсказуемый `invite_token` (UUID, CSPRNG).
- 4 места. Первые три приглашённых занимают свободные; четвёртый сверх лимита
  отклоняется (`rejected`).
- Гость без регистрации: `hello` → временный `guest_id` + ник.
- Одна фракция на игрока; конфликт выбора сервер объясняет честно.
- Незапущенная комната истекает по таймеру; отключение → переподключение по
  `guest_id` возвращает в ту же партию; повторная команда отклоняется по `seq`;
  перебор инвайтов ограничен (rate-limit).

## Авторитетность

- `intent` принимается только от текущего игрока, с валидным `seq`, в нужной фазе.
- Сервер повторно проверяет через `Game.can_*` (право, геометрия, ресурсы), затем
  применяет и рассылает `state` + `event`.
- Клиент не может записать очки/фракцию/чужой ход — только намерения.

2. [ ] `scripts/server.gd` — headless MainLoop: слушает порт, держит список

   (локальный режим оставить для тестов).

## Экспорт сервера

Dedicated server: `godot --headless --path . --script res://scripts/server.gd`
(в будущем — отдельный export preset `Linux server`). Порт/адрес — через
`--port=`, `--bind=`.
